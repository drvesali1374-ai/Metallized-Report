# 🏭 سامانهٔ مانیتورینگ صنعتی رول‌ها — نسخهٔ ۲٫۲

## 🆕 تغییرات نسخهٔ ۲٫۲

- **نگاشت ستون‌های «رول‌های موجود»:** فیلد «عرض» به «عرض اولیه» (محاسبات رول‌های خام) تغییر نام یافت و فیلد جدید «عرض» (محاسبات رول‌های برش‌خورده) اضافه شد؛ ستون «موقعیت فعلی» به‌صورت خودکار به فیلد «وضعیت» نگاشت می‌شود.
- **گزارش تحلیل گروهی ستاپ‌ها:** روش محاسبهٔ جدید — جمع عرض رول مادر (Σ تعداد)، یونیک رول مادر (عرض‌های یکتا)، جمع عرض الگوی برش (Σ تعداد عرض الگو × تعداد ست)، یونیک عرض الگوی برش (عرض‌های یکتای برش).
- **بخش «رول‌های برش‌خورده» (فرزند):** رکوردها با کلید «عرض برش‌خورده + شماره ستاپ» از الگوهای برش ستاپ‌ها ساخته می‌شوند؛ ۱۱ ستون (عرض، ستاپ، مقدار موجود، مقدار در ستاپ، مقدار برش‌نخورده، X/U/Q/T، پای کار، پالت شده — همه با تعداد + وزن)؛ وزن = عرض × ۰٫۳۶۲ × تعداد با جداسازی سه‌رقمی نقطه‌ای؛ تشخیص برش‌خورده از حرف بازوی L/R بعد از M در شناسهٔ رول؛ پنل مرتب‌سازی مشابه رول‌های خام (با دکمهٔ مخفی/ظاهر) + فیلتر پیشرفتهٔ همهٔ ستون‌ها زیر سرستون‌ها + نمایش حداقل ۵۰ رکورد با اسکرول.
- **قوانین زمان متالایز (هر دستگاه):** پنل جدید در تنظیمات — (دستگاه، متراژ استاندارد از قوانین موجود، تعداد در شیفت) → مدت زمان خودکار = ۷۲۰ ÷ تعداد دقیقه (شیفت ۱۲ ساعته).
- **ستون‌های «مانده زمان ستاپ» (مدت × تعداد) و «مانده زمان تولید شده» (مدت × خام موجود)** در گزارش تولید ستاپ‌ها.
- **داشبورد:** کارت‌های «رول‌های متالایز شده» و «کل رول‌های ستاپ‌ها» جای خود را به «مانده زمان متالایز — ستاپ/تولید شده» دادند + نمودار میله‌ای مانده زمان به تفکیک دستگاه.

وب‌اپلیکیشن **کاملاً آفلاین** برای مدیریت و ردیابی چرخهٔ عمر رول‌های صنعتی:

```
رول خام  →  متالایز  →  برش  →  رول‌های کوچکتر
```

سیستم عمدتاً یک **Roll Monitoring / Setup Management / Production Traceability System** است — نه صرفاً یک داشبورد اکسل.

> **اجرا:** فقط روی `index.html` دابل‌کلیک کنید — بدون Node.js، بدون سرور، بدون اینترنت، بدون نصب.

## 🏗 معماری Offline-First

| اصل | پیاده‌سازی |
|---|---|
| بدون سرور | تمام منطق در Vanilla JS سمت مرورگر |
| بدون CDN | SheetJS و Dexie و فونت‌ها لوکال در `lib/` |
| ذخیره‌سازی | IndexedDB مرورگر (Dexie.js) |
| مهاجرت امن | v1 → v2 با بازسازی نرمال‌شدهٔ داده‌های قدیمی |
| Traceability آینده | فیلد `parentRollNumber` در مدل رول رزرو شده |
| امنیت | Escape کامل HTML، بدون Console dump داده |

### خط لولهٔ داده (Single Source of Truth)

```
Excel خام  →  Normalization  →  قوانین متراژ  →  گروه‌بندی خام
     →  متالایز یونیک  →  تطبیق ستاپ  →  تخصیص ظرفیت‌محور
     →  گزارش ستاپ + هشدارها  →  داشبورد / جدول‌ها / گزارش‌ها
```

تمام صفحات از **یک موتور محاسبه** (`calculateProductionState()`) تغذیه می‌کنند — هیچ عددی در دو صفحه متفاوت محاسبه نمی‌شود. Cache داخلی موتور فقط با تغییر واقعی داده بی‌اعتبار می‌شود (محاسبهٔ مجدد ۱۰۰ هزار رکورد: ~۰٫۹ ثانیه).

## 📜 قوانین کسب‌وکار

### ۱) تشخیص رول خام (rolls.xlsx)
- نوع فیلم شامل **R/r** (Case-Insensitive): `filmType.toLowerCase().includes('r')`
- **و** شماره پالت خالی: `null / undefined / "" / "   "` (مقادیر `0`، `P0`، `"0:1"` خالی **نیستند**)

### ۲) متالایز (Archived Rolls.xlsx)
- رکوردهای دارای R/r
- **یونیک بر اساس شماره رول** (هر رول فقط یک‌بار)
- از شماره رول برای استخراج بخش قبل از M استفاده **نمی‌شود**

### ۳) قوانین متراژ استاندارد
`ضخامت + بازهٔ [حداقل، حداکثر] → متراژ استاندارد` — مرزها **شامل‌اند** (`min ≤ len ≤ max`)
- بدون قانون منطبق → `standardLength = null` → عدم تطبیق با ستاپ
- هم‌پوشانی بازه‌های یک ضخامت **ممنوع** (اعتبارسنجی مرکزی، غیرقابل دور زدن)

### ۴) ستاپ‌ها
- فیلدها: شماره ستاپ، دستگاه (فقط **۱/۲/۳** — دستگاه‌های متالایز)، عرض مادر، ضخامت، متراژ استاندارد، تعداد، الگوی برش
- **کلید یکتا:** `عرض + شماره ستاپ + متراژ استاندارد + شماره دستگاه + الگوی نرمال‌شدهٔ برش` — **ترتیب قطعات الگو بی‌اثر است** (`1200-1050` ≡ `1050-1200`؛ `800-930-930` ≡ هر جایگشت دیگر) و الگوهای واقعاً متفاوت ستاپ‌های متفاوت می‌سازند
- **ارث‌بری ضخامت:** رکورد جدیدِ ستاپ موجود → ضخامت قفل خودکار
- **آبشار ضخامت:** تغییر ضخامت در ویرایش → با تأیید کاربر، همهٔ رکوردهای همان ستاپ تراکنشی به‌روزرسانی می‌شوند
- دراپ‌داون متراژ استاندارد فقط مقادیر تعریف‌شدهٔ ضخامت انتخابی را نشان می‌دهد
- **ثبت گروهی (Bulk Paste):** Paste از اکسل با ساختار TSV — خط فرد = عرض‌های الگو + تعداد رول در انتها، خط زوج = عرض رول‌های مادر متناظر (سلول خالی = ادامهٔ مادر قبلی؛ الگو می‌تواند یک/دو/چندتکه باشد). ستاپ‌های هم‌کلید در کل Batch تجمیع می‌شوند؛ پیش‌نمایش با خطای هر رکورد؛ Commit فقط در صورت معتبر بودن همه و در **یک تراکنش واحد**

### ۵) الگوی برش
- ورودی با `-`: `1100-1170` یا `600-600-600-600` (ارقام فارسی هم پذیرفته می‌شود)
- هر بخش باید عدد مثبت باشد؛ قانون: **مجموع ≤ عرض مادر** (کمتر مجاز + نمایش «پرت عرض»)
- بازخورد زنده هنگام تایپ + کارت‌های نمایشی در جدول

### ۶) تطبیق و تخصیص
- **کلید خام (۳فاکتوری):** `عرض + متراژ استاندارد + شماره ستاپ`
- **کلید متالایز (۲فاکتوری):** `عرض + شماره ستاپ` (عمداً متفاوت)
- **تخصیص ظرفیت‌محور:** ستاپ‌های دارای کلید مشترک بر اساس تعداد **صعودی** مرتب و تا سقف ظرفیت پر می‌شوند؛ هر رول فقط یک‌بار تخصیص می‌یابد؛ مازاد = Unallocated
- **فرمول:** `برش‌نشده = تعداد ستاپ − (خام موجود + متالایز)`
- **مقدار منفی → نمایش ۰ + هشدار «مغایرت ظرفیت»** (مغایرت هرگز پنهان نمی‌شود)

### ۷) تصمیم معماری: تخصیص رول‌های خام
رول‌های خام نیز (مشابه متالایز) بین ماشین‌های دارای کلید ۳فاکتوری مشترک ظرفیت‌محور تخصیص می‌یابند تا **شمارش مضاعف** بین ماشین‌های هم‌کلید رخ ندهد (اصل §88). مازاد خام در مرکز هشدارها گزارش می‌شود.

## 🛠 قابلیت‌ها

| بخش | امکانات |
|---|---|
| **داشبورد** | ۴ KPI + مرکز هشدار کیفیت داده با **Drill-down رکوردهای عامل هر هشدار** + فرمول‌های زنده |
| **ورود داده‌ها** | Drag & Drop، عنوان‌های کاربرپسنده («رول‌های موجود» / «سابقه رول‌ها (آرشیو)» — نام واقعی فایل برای Audit)، گزارشنمای اعتبارسنجی **با موارد مشکل‌دارِ قابل کلیک**، هش فایل، نسخه‌بندی Dataset، تأیید جایگزینی |
| **رول‌ها** | گروه‌بندی خام + وضعیت تطبیق + مرتب‌سازی چندمرحله‌ای کشیدنی ماندگار (**شامل فیلد «وضعیت»**) + **جزئیات گروه با ستون‌های مپ‌شده و انتخاب/ترتیب ستون** + تب برش‌خورده (آمادهٔ معماری) |
| **ستاپ‌ها** | فرم هوشمند (ارث‌بری/دراپ‌داون وابسته/الگوی زنده) + **ثبت گروهی Bulk Paste با پیش‌نمایش و Commit تراکنشی** + ویرایش/حذف + گزارش تولید + مودال Audit تخصیص |
| **تنظیمات** | **نگاشت ستون‌های اکسل (مستقل برای هر Dataset)** + مدیریت قوانین متراژ + Backup/Restore + مدیریت داده‌ها + سابقهٔ Import |

> نمایش «عرض» در کل برنامه بدون جداکنندهٔ هزارگان است (`1200` نه `1,200`) — فقط لایهٔ Presentation، داده‌ها و محاسبات دست‌نخورده.

## 🚀 نحوهٔ اجرا

1. پوشهٔ `roll-monitor` را در سیستم خود کپی کنید.
2. روی `index.html` دابل‌کلیک کنید.
3. مرورگرهای پیشنهادی: Chrome / Edge / Firefox به‌روز.

### اولین استفاده
1. تب **«ورود داده‌ها»** → دو فایل `rolls.xlsx` و `Archived Rolls.xlsx` را ایمپورت کنید.
2. تب **«تنظیمات»** → قوانین متراژ استاندارد را برای ضخامت‌های خود تعریف کنید.
3. تب **«ستاپ‌ها»** → ستاپ‌ها را ثبت کنید.
4. تب **«داشبورد»** و **«رول‌ها»** به‌صورت بلادرنگ به‌روزرسانی می‌شوند.
