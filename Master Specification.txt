# Master Specification — بازطراحی و توسعه کامل Roll Monitor

## 1. نقش و مأموریت شما

شما یک Senior Frontend Engineer و Software Architect متخصص در ساخت Web Applicationهای صنعتی، Offline-First و Data-Intensive هستید.

یک پروژه موجود با نام:

`Metallized-Report`

و مسیر:

`roll-monitor/`

در اختیار شماست.

قبل از هرگونه تغییر، **تمام فایل‌های موجود در مسیر `roll-monitor` را با دقت بررسی کنید** و معماری، UI، دیتابیس، نام‌گذاری‌ها، توابع موجود، وابستگی‌ها و محدودیت‌های فعلی پروژه را کاملاً درک کنید.

هدف این نیست که صرفاً چند قابلیت به پروژه فعلی اضافه شود؛ هدف، تبدیل پروژه فعلی به یک سیستم حرفه‌ای:

> **Roll Monitoring / Setup Management / Production Traceability System**

است.

هرجا معماری فعلی برای نیازمندی‌های جدید مناسب نیست، آن را با حفظ سازگاری و منطق صحیح بازطراحی کنید.

نیازمندی‌ها و قوانین کسب‌وکار که در این سند مشخص شده‌اند **قطعی هستند**.

# 4. فلسفه اصلی سیستم

سیستم را صرفاً یک Excel Dashboard در نظر نگیرید.

این برنامه در اصل یک:

> **سیستم مدیریت و ردیابی چرخه عمر رول**

است.

چرخهٔ کلی:

```text
رول خام
   ↓
متالایز
   ↓
برش
   ↓
رول‌های کوچکتر
```

و `Archived Rolls` تاریخچهٔ وضعیت‌های قبلی رول‌ها را نگهداری می‌کند.

بنابراین سه مفهوم باید کاملاً از هم تفکیک شوند:

```text
CURRENT STATE
وضعیت فعلی رول‌ها

HISTORY
تاریخچه رول‌ها

SETUP PLAN
برنامه و ظرفیت ستاپ‌ها
```

---

# 5. ساختار واقعی حرکت رول‌ها

این نکته بسیار مهم است.

رول خام ابتدا در بخش `rolls` قرار دارد.

مثلاً:

```text
F3504730451R4
```

وقتی متالایز می‌شود:

```text
F3504730451R4M12
```

رول قبلی:

```text
F3504730451R4
```

از بخش فعلی به Archive منتقل می‌شود.

یعنی Archive شامل نسخهٔ قبلی رول است.

سپس اگر:

```text
F3504730451R4M12
```

برش بخورد و به دو رول تبدیل شود:

```text
F3504730451R4M1213R5
F3504730451R4M1213L4
```

رول مادر قبل از برش:

```text
F3504730451R4M12
```

به Archive منتقل می‌شود.

بنابراین:

> Archive تاریخچهٔ Roll Stateهاست.

Archive نباید به‌صورت ساده «لیست رول‌های متالایز شده» فرض شود.

# 6. تشخیص Roll خام

یک Roll خام از فایل:

`rolls.xlsx`

رولی است که:

1. مقدار `نوع فیلم` آن دارای R یا r باشد.
2. مقدار `شماره پالت` خالی باشد.

بررسی R باید Case-Insensitive باشد.

یعنی:

```javascript
filmType.includes('R')
```

یا معادل Case-Insensitive آن.

مقادیر زیر برای شماره پالت «خالی» محسوب می‌شوند:

```text
null
undefined
""
"   "
```

اما این‌ها خالی نیستند:

```text
0
P0
0:1
```

---

# 7. تشخیص Roll خام متالایز شده

از فایل:

`Archived Rolls.xlsx`

تمام رکوردهایی که:

```text
نوع فیلم دارای R یا r
```

هستند، به‌عنوان رول‌های خامی در نظر گرفته می‌شوند که از وضعیت خام فعلی عبور کرده‌اند.

در این قسمت **نباید از شماره رول برای استخراج بخش قبل از M استفاده شود.**

این روش اشتباه است و نباید پیاده‌سازی شود.

رکوردهای استخراج‌شده باید بر اساس شماره رول Unique شوند.

مثلاً:

```text
F3504730451R4
F3504730452R3
F3504730451R4
F3504730453R2
```

تبدیل شود به:

```text
F3504730451R4
F3504730452R3
F3504730453R2
```

هر Roll فقط یک بار در شمارش متالایز شده لحاظ شود.

# 9. Normalization Layer

یک لایهٔ مرکزی برای Normalize کردن داده‌های Excel ایجاد کنید.

برای مثال دادهٔ داخلی سیستم می‌تواند مفهومی شبیه این داشته باشد:

```javascript
{
    rollNumber,
    width,
    actualLength,
    thickness,
    filmType,
    palletNumber,
    setupNumber,
    source
}
```

در نتیجه:

```text
Excel Columns
      ↓
Normalization
      ↓
Internal Roll Model
      ↓
Business Logic
```

این کار باعث می‌شود اگر در آینده ساختار Excel کمی تغییر کرد، کل سیستم نیاز به بازنویسی نداشته باشد.

# 14. Transaction Safety

عملیات مهم Database باید Transactional باشند.

به‌خصوص:

* Import
* Replace Dataset
* Save Setup
* Edit Setup
* تغییر ضخامت گروه
* Save Standard Rule
* Delete Rule
* Backup Restore

در Import حجیم، از Bulk Operations مناسب استفاده کنید.

هدف:

```text
Either complete successfully
OR
rollback / do not leave a half-imported dataset
```

باشد.

# 15. Standard Length Rules

در Settings بخشی برای تعریف قوانین متراژ استاندارد ایجاد کنید.

ساختار Rule:

```text
Thickness
Minimum Actual Length
Maximum Actual Length
Standard Length
```

واحد Thickness:

```text
Micron / میکرون
```

مثلاً:

```text
20 | 17000 | 24000 | 20000
20 | 35000 | 45000 | 40000
```

یعنی:

```text
17000 <= ActualLength <= 24000
→ StandardLength = 20000
```

و:

```text
35000 <= ActualLength <= 45000
→ StandardLength = 40000
```

---

# 16. Boundary Rules

هر دو مرز بازه شامل هستند.

یعنی:

```text
17000
```

و:

```text
24000
```

هر دو داخل بازه‌اند.

فرمول:

```text
minLength <= actualLength && actualLength <= maxLength
```

---

# 17. No Matching Rule

اگر رول هیچ Ruleای برای ضخامت خودش نداشت:

```text
standardLength = null
```

باشد.

این Roll نباید در Match با Setup شرکت کند.

مثلاً:

```text
Thickness = 20
ActualLength = 28000
```

اگر هیچ Ruleای 28000 را پوشش ندهد:

```text
StandardLength = null
```

و Match انجام نشود.

---

# 18. جلوگیری از Overlap قوانین

برای یک ضخامت، قوانین نباید با یکدیگر Overlap داشته باشند.

این غیرمجاز است:

```text
20 | 17000 | 24000 | 20000

20 | 22000 | 30000 | 25000
```

چون:

```text
22000–24000
```

در هر دو Rule قرار دارد.

هنگام Save Rule این موضوع بررسی شود و ذخیره در صورت Overlap متوقف شود.

این کنترل را فقط در UI انجام ندهید؛ منطق Validation باید مرکزی باشد.



# 27. Cutting Pattern

کاربر باید بتواند الگوی برش را با `-` وارد کند.

مثلاً:

```text
1100-1170
```

یا:

```text
600-600-600-600
```

برای عرض مادر:

```text
2270
```

مثال اول:

```text
1100 + 1170 = 2270
```

مثال دوم:

```text
600 + 600 + 600 + 600 = 2400
```

---

# 28. Cutting Pattern Validation

هر بخش باید عدد معتبر باشد.

مثلاً:

```text
1100-1170
```

به:

```text
[1100, 1170]
```

تبدیل شود.

سپس:

```text
sum(patternWidths)
```

محاسبه شود.

قانون:

```text
PatternSum <= MotherWidth
```

اگر:

```text
PatternSum > MotherWidth
```

ثبت ممنوع شود.

اما اگر کمتر باشد، کاملاً مجاز است.

مثلاً:

```text
MotherWidth = 2270

Pattern:
1100-1100

Sum = 2200

Remaining = 70

✓ معتبر
```

# 42. Metallized Allocation

این قسمت بسیار مهم است.

فرض کنید Setupها:

```text
Width = 2120
Setup = 140
```

هستند.

و:

```text
Machine 1 → Count 5
Machine 2 → Count 8
```

```text
2120-140
```

دارند.

اگر ۹ Roll متالایز شده برای این کلید پیدا شود، نباید برای هر دو رکورد ۹ ثبت شود.

بلکه:

```text
Machine 1 → 5

```

باشد.

مجموع:

```text
9
```

# 43. Allocation Algorithm

برای هر گروه:

```text
Width + SetupNumber
```

تمام Setupهای دارای این کلید را پیدا کنید.

سپس آن‌ها را بر اساس:

```text
Setup Count ASC
```

مرتب کنید.

مثلاً:

```text
Machine 2 → 4
Machine 3 → 7
Machine 1 → 10
```

اگر ۱۵ Roll متالایز شده داشته باشیم:

```text
Machine 2 → 4
Machine 3 → 7
Machine 1 → 4
```

شود.

هر Roll فقط یک بار تخصیص داده شود.

---

# 44. Allocation Capacity Rule

برای هر Setup:

```text
AllocatedMetallized <= SetupCount
```

باشد.

اگر تعداد متالایزها بیشتر از مجموع ظرفیت تمام Setupهای دارای آن کلید باشد، مازاد نباید به‌صورت مصنوعی تخصیص داده شود.

مثلاً:

```text
Machine 1 = 5
Machine 2 = 8
```

ظرفیت کل:

```text
13
```

اگر ۱۸ Roll وجود داشته باشد:

```text
Machine 1 → 5
Machine 2 → 8
Unallocated → 5
```

و سیستم باید این مغایرت را به کاربر نشان دهد.

# 50. Uncut Rolls

فرمول اصلی:

```text
Uncut =
SetupCount
-
(
RawExisting
+
Metallized
)
```

```text

```

نتیجه:

```text

```

# 51. Negative Uncut

اگر:

```text
Raw + Metallized > SetupCount
```

باشد، مقدار منفی از نظر فیزیکی «رول منفی» نیست.

پیشنهاد UX:

```text
Uncut = max(0, calculatedUncut)
```

اما مغایرت نباید پنهان شود.

مثلاً:

```text

```

اگر روش فنی بهتری دارید، می‌توانید آن را اجرا کنید، اما مفهوم مهم این است که **مغایرت داده باید قابل مشاهده باشد.**

# 56. Performance

ممکن است Excel شامل ده‌ها هزار یا حتی صدها هزار رکورد باشد.

بنابراین:

* از Loopهای تکراری غیرضروری خودداری کنید.
* Grouping را با Map انجام دهید.
* Unique را با Set انجام دهید.
* از Bulk Database Operations استفاده کنید.
* دادهٔ خام را چندین بار از IndexedDB نخوانید.
* در صورت نیاز Derived Data را Cache کنید.
* Render جدول‌های بزرگ را بهینه کنید.

در صورت نیاز Pagination، Virtual Rendering یا محدودسازی Render DOM را پیشنهاد و پیاده‌سازی کنید.

# 109. دستور نهایی

ابتدا **تمام فایل‌های فعلی `roll-monitor` را بررسی و درک کن.**

سپس Architecture فعلی را با این Specification مقایسه کن.

پس از آن:

```text
Analyze
 ↓
Design
 ↓
Refactor where necessary
 ↓
Implement
 ↓
Validate
 ↓
Test
 ↓
Document
```

را انجام بده.

از پیاده‌سازی سریع و سطحی خودداری کن.

هدف، ساخت یک سیستم صنعتی قابل اتکا، قابل نگهداری، قابل توسعه و قابل Audit است؛ نه صرفاً اضافه کردن چند جدول و فرم.

هرجا بتوانی با یک طراحی بهتر، سیستم را:

* سریع‌تر
* دقیق‌تر
* قابل فهم‌تر
* مقاوم‌تر در برابر خطای کاربر
* قابل توسعه‌تر
* حرفه‌ای‌تر

کنی، از خلاقیت خود استفاده کن و آن راه را انتخاب کن.

اما تمام Business Ruleهای مشخص‌شده در این سند باید بدون کم‌وکاست رعایت شوند.
